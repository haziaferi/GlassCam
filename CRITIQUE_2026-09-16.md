# Critique — GlassCam 4.3.82 (`com.hazia.glasscam`), layout and feature function

**Evidence.** Debug APK built from this tree (arm64, `tools/critique/logs/build.log`, exit 0), installed on the OnePlus 9 Pro (LE2123, Android 14, 1080×2412 @ 480 dpi = 804×360 dp landscape), driven over adb in English (per-app locale), 128 screenshots + uiautomator dumps in `tools/critique/screenshots/`. Repo-side measurements from `tools/critique/measure.py` (`measured.json`), rendered-side from `tools/critique/analyse.sh`, layout search from `tools/critique/layout_spec.json` + `scorers.py` (`opt_run/`). Reference apps walked on the same phone: upstream FreeDcam, Open Camera, stock OnePlus Camera, ProShot, Fossify Camera, Libre Camera, Manual Camera Pro, MA Camera (`com.vayunmathur.camera`, "Camera" v2.6.5, installed 2026-09-16 00:36).

**Voices.** Rows marked *measured* are arithmetic or observed device behaviour; rows marked *judgement* are mine. Screenshot numbers refer to `tools/critique/screenshots/NN_*.png`.

## Top priorities

1. **[High] Camera1 API is dead on this device** — *measured.* Etc ▸ API ▸ camera1 leaves a live preview with **no controls at all** (75–77): `NullPointerException` in `PictureModule.createPreview` (`apis/camera1/modules/PictureModule.java:201`, `Preview` is null) aborts `ParametersHandler.initParameters`, so the UI is never built. Switching back to camera2 does **not** rebuild it (79); only a force-stop recovers.
   Fix: create the preview post-processing `Preview` before `PictureModule.InitModule` runs on the Camera1 path (or null-guard and fall back to a plain `SurfaceTexture`), and make `CameraApiManager.switchCamera` tear down and re-inflate `NextGenCameraUiFragment` after an API change instead of only restarting the camera. Until then, hide the camera1 row on devices where `Camera1.initCamera` throws.

2. **[High] AF-bracket range can never be set** — *measured.* `NextGenManualsFragment.java:240` shows `AfBracketSettingsView` only when `currentButton instanceof ManualButtonMF` — the legacy class — while the NextGen strip creates `NextGenMfItem` (the check at line 157 uses the right class). Tapping the focus button in Af-Bracket mode opens the plain focus seekbar (53); Near/Far/frames are unreachable, so every bracket runs with the defaults (10 frames, 52).
   Fix: `instanceof NextGenMfItem` at line 240 (one token), then verify with the walk step "AF bracket → focus button".

3. **[High] Gallery options are wired to the wrong actions, and the stacker is unreachable** — *measured.* `viewer/gridview/models/ButtonOptionsModel.java:10` labels `{Delete File, StackJpeg, Raw to Dng}` against listeners `{delete, rawToDng, dngStack}`: tapping **RAW TO DNG** enters DNGSTACK selection (67) and then toasts "DNG stacking needs files with direct filesystem access…" (68); tapping **STACKJPEG** enters RAWTODNG mode (69). `"DngStack"` is commented out of the array, so the stacker has no honest entry point anyway.
   Fix: align the two arrays (`{Delete File, Raw to Dng}` ↔ `{delete, rawToDng}`), drop the stack entry until the native `TIFFOpen` path accepts a file descriptor, and add an empty-state line to RAWTODNG mode ("No raw Bayer files in this folder").

4. **[High] The 7-tab settings strip clips "Etc" to 15 dp and the scroll gesture closes the drawer** — *measured.* uiautomator reports the Etc tab at 15.3×48 dp (23); six tabs fit the 60 % panel. Swiping the strip right-to-left is consumed by the pager as "close settings" (31). Etc is reachable only as a side effect of selecting Camera, which auto-scrolls the strip. *Judgement:* a first-time user cannot find Storage Location, API or Geo-tag.
   Fix: `tabMode="scrollable"` is already in use — the real fix is fewer tabs (merge Interval into Picture, Raw into Picture as a section) or a two-row TabLayout on `< sw600dp`; and give the strip `requestDisallowInterceptTouchEvent` while it is scrollable.

5. **[High] Row headers ellipsize in the two-column settings grid** — *measured.* "Use GlassCam Dn…", "Enable to use cust…", "Optical Image Stabilis…", "Duration till interval…", "Check for new up…", "Preview PostProcessi…", "Switch width and …", "Auto Zoom on Ma…" (25–34). Column is 224 dp; header 16 sp bold with a value/switch on the same line.
   Fix: single-column list on phones (`spanCount=1` under 600 dp), or header on its own line with the value right-aligned below at 14 sp. The `values-sw600dp` bucket can keep two columns.

6. **[High] Shutter-column captions marquee and clip** — *measured.* `textView_front` under the focus glyph scrolls "Continouse Picture" through a 40 dp column (01–05 show "Continou", "ntinouse", "Contin", "icture"); "Pic"/"Af-Brack…" clip under the module glyph; a stray "0" renders at x≈95 dp in the left letterbox band (52). *Judgement:* animated text next to the shutter is the single most distracting thing on the screen.
   Fix: caption = the value's short form (Auto/Macro/C-AF/C-Video/Off; Pic/Vid/Int/AEB/AFB), 9 sp, `ellipsize=none`, `singleLine`, no marquee; widen the column to 56 dp (see optimizer result).

7. **[Med] Copy defects that read as bugs** — *measured.* Help page 4 "…to close Manual)" stray paren (04); "Force Wide Preview" carries the DNG-converter description "Only for 16bit Dng(RAW_SENSOR)…" (32); Storage Location still says "NOTE: On KitKat… Lollipop and Marshmallow…" in a minSdk 30 app (29); "Face Dectection", "Continouse", "True Potrait", "reseted", "wich"; "Picture Size :" (space before colon); trailing-colon inconsistency ("WB" vs "Scene:"); Timelapse-frames row has no header at all — just `+ − 30.0 fps` (23); value pickers have no title and "Back" is styled like a value (36).
   Fix: one pass over `strings.xml` (list in §Copy), `settings_expandable_childs_number.xml` gets a header, `NextGenSettingValuePickerAdapter` gets a title row and a distinct Back chip.

8. **[Med] Horizon level is ambiguous and expensive** — *judgement + measured.* Two roll ticks at 11/5 o'clock **and** a pitch arrow at top-centre, hairline strokes, no number, no "level now" colour state, drawn over the composition crosshair (40, zoom in `_z_level.png`). *Measured:* `CompassDrawer` invalidates continuously — uiautomator cannot get an idle state while it is on (every dump failed until it was switched off), which is also a battery cost. Every reference with a level (ProShot, MA Camera, Open Camera) shows **one** bar that turns green/solid when level.
   Fix: one horizontal bar + short centre tick, 2 dp stroke with a 1 dp dark outline, green at |roll| < 0.5°, numeric roll in 10 sp beside it; invalidate only when the reading changes by ≥ 0.2°; auto-hide 2 s after level unless the setting says "always".

9. **[Med] No gallery from the camera screen** — *measured.* There is no thumbnail or button; GlassGallery is a second launcher icon (54). Every reference app has a 1-tap gallery from the viewfinder. Add the last-capture thumbnail as a cell in the shutter column (the optimizer places it directly under the shutter).

10. **[Med] Contrast is scene-dependent and undefended** — *measured.* 92 of 145 text elements fall below 4.5:1 on a mid-grey scene: white 10 dp info-overlay text 4.0:1, white shutter-column captions 3.95:1, lime `#64DD17` manual values 2.24:1, `#99FFFFFF` descriptions 2.46:1 (all ≥ 7:1 over black). The settings scrim rescues its rows (lime 8.6:1, secondary 6.4:1 over scrim-on-grey). The info overlay's `#02000000` background is effectively no background.
    Fix: give the info overlay and the caption texts the same `#B3000000` pill the scrim uses, or a 1 dp `shadowRadius` outline as `StyledTextView` already does for the manual strip.

11. **[Med] Recording state is nearly invisible** — *judgement.* Red square inside the shutter plus a ~9 sp green timer overlapping the shutter's lower edge (47); the info overlay keeps showing the *picture* format ("Jpg+16bitDng") while in video mode (46) and drops the storage-left count. Add a red border on the preview or a REC pill in the info overlay, put the timer in the overlay at 12 sp, show the video profile there in video mode.

12. **[Med] Video Profile Editor and DNG converter are a different app** — *measured.* `#aaa` ground, white text 2.32:1, stock pink `colorAccent` switch, nav bar visible (70–71); CamelCase labels ("AudioBitRate:"). Restyle on the NextGen tokens (scrim, lime, 16 dp radius) with a title row.

13. **[Med] Session state leaks** — *measured.* Module survives force-stop (a relaunch fired a 10-frame AF bracket on the first shutter tap, 103); burst stayed at 10 after leaving AF-bracket; the help overlay returns on every launch until its checkbox is ticked (104); ISO drag on the seekbar silently switches ISO to manual ("450" replaces "(A)6400") with no auto-return affordance (22, 40). Reset module/burst to Picture/1 on cold start; show the help only on first run; add an "A" tap-target on the seekbar's auto value.

14. **[Low] Seekbar labels clip and the exposure list starts at 1/100000 s** — *measured* (16–17, `_z_seekbar.png`). Clamp the range to the sensor's `SENSOR_INFO_EXPOSURE_TIME_RANGE` and label every fifth stop.

15. **[Low] Swallowed exception in video** — *measured.* `NumberFormatException: For input string: "Auto"` at `VideoModuleApi2.java:461` on every video session configure (logcat); recording still works. Parse the ISO/shutter value defensively.

## Dimension-by-dimension

**First impression (2-second read)** — *judgement.* The eye lands on the white 80 dp shutter (measured focal point 0.79, 0.53 by edge energy — correct). Purpose is clear: a manual camera. Register is "engineering tool": icon-font glyphs, no colour except the lime state, a 4:3 preview letterboxed inside a 20:9 screen with 162 dp black bands each side. Chrome covers 5 % of the frame (measured), which is admirably restrained. The marquee caption is the one thing that fights the calm.

**Visual hierarchy** — *judgement.* Entry point: shutter. Second: the manual strip's eight icon+value pairs along the preview's bottom edge (they are inside the preview, so they compete with the scene). Third: the seven text-switches. The info overlay (time, format, size, left, battery) reads as a fourth tier but carries the state you check most (format, storage). Whitespace is structural (the bands) rather than designed — the left band holds only the histogram when enabled and the stray "0".

**Typography** — *measured.* Scale in use: 9 sp (manual values), 10 dp (info overlay — `dimens.xml: cameraui_infooverlay_textsize=10dip`, not sp, so it ignores font scaling), 12/14/16 sp (settings description/value/header), 13 sp (tabs), 22 sp (glyphs), 40 dp (`nextgen_cameraui_textswitch`, used as a text size in `styled_textview.xml`). Two text dimens are authored in dp. *Judgement:* the settings ladder 12/14/16 is too tight for a two-column grid; 12/14/18 with the header on its own line would separate the levels. The icon font is the app's signature and is consistent everywhere except the popups' flash chips, which are four near-identical 12 px glyphs without captions (09).

**Colour and contrast** — *measured.* 20 colours defined; the NextGen tokens (`#B3000000` scrim, `#64DD17` accent, `#99FFFFFF` secondary, `#33FFFFFF` outline, `#4064DD17` ripple) are coherent and used by the drawer, strip and captions. Stock `colorPrimary #3f51b5` / `colorAccent #FF4081` are still defined and *do* appear — the pink switch thumb in the Video Profile Editor (70). 84 hard-coded colours in layouts, 5 of them `#02000000` backgrounds that do nothing. Contrast table: see `measured.json`; worst rows in §Top priorities 10. Rendered palette of the main screen (k-means): `#080808 #181818 #180808 #181828 #282828`, mean chroma 3 — the UI adds no colour of its own except the lime, which is right for a camera.

**Layout and spacing** — *measured.* 150 margin/padding literals across 40 layouts; 25 distinct values (0–150 dp); 128 are off the 8 dp grid, 122 off the 4 dp grid (5 dp, 10 dp, 29 dp, 93 dp, 141 dp, 147 dp). The shutter column is a ragged two-column stack: three rows above the shutter with two empty left cells, two rows below. Tap targets: text-switch glyphs 30×29 dp (declared column 40 dp), manual buttons 40–71×25 dp, settings tab Etc 15 dp, gallery buttons 30–40 dp, curve-view buttons 30 dp, switches 47×27 dp — 18 declared-under-48 dp targets in XML and 22 observed on device across the camera, drawer and gallery screens. The `values-sw600dp` bucket scales the gauge and waveform ×1.28 and the settings text ×1.25; it was not verified (no tablet). The preview is 4:3 in picture mode and switches to 16:9 in video mode (46) — the chrome does not move with it, so in video the strip sits inside the picture and the histogram pill sits over the frame.

**Copy** — *measured.* 278 default strings, 130 Italian entries (5 empty) — 45 % coverage by key; 148 keys have no Italian at all. 74 strings hard-coded in layouts (`help_fragment.xml` "Large Text"/"Next"/"don't show again", the whole video profile editor, curve view, DNG converter). Tab titles hard-coded in `SettingTabPagerAdapter`. Typos: Continouse, Dectection, Potrait, reseted, wich, simpeltext (layout name). Obsolete: the KitKat/Lollipop storage note. Wrong: Force Wide Preview description. *Judgement:* CTAs are mostly nouns ("Video Profile Editor", "Run FeatureDetector", "Dump vendor keys") — fine for a tool, but "Check for new updates" is a switch for a feature that is hard-off (`ReleaseChecker.isGithubRelease=false`) and still links to KillerInk's GitHub.

**Consistency** — *judgement.* Three visual systems coexist: NextGen (camera + drawer, coherent), the viewer (black, white glyph column, stock grey uppercase buttons), and the AppCompat-default forms (profile editor, DNG converter, curve view — `#aaa`/`#424242`/`button_notclicked`). Corner radius: 16 dp on the drawer and seekbar pill, 0 elsewhere. The signature element (icon font + lime state) stops at the drawer's edge.

**Interactivity** — *measured/judgement.* Ripple on settings rows (new `NextGenRowFeedback`) — good. No pressed state on the text-switches or manual buttons beyond the lime colour swap. No visible focus ring anywhere (keyboard/d-pad users are out of scope for a phone camera, but the volume-key handler exists). Gestures: L→R opens settings, R→L closes, up opens manuals — the tab strip's own horizontal scroll collides with the close gesture (31). Back from the image viewer exits the whole gallery activity (after 57). The drawer remembers its tab but the list loses its scroll position after a picker (37/38), so the same coordinate hits a different row.

**Fit for purpose** — *judgement.* For one owner who wants RAW + manual on an unrooted phone, the core loop (frame → manual value → shutter → DNG on disk) works and is fast. What does not fit: landscape-locked camera vs portrait gallery; no gallery from the viewfinder; a settings drawer that hides four of the most-used rows behind an unreachable tab; a level you cannot trust at a glance.

## Horizon level (own section)

*Measured:* `HorizontLineFragment`/`CompassDrawer`, `horizon_gauge_width` 250 dp (320 dp on sw600dp), enabled via Preview ▸ Image Level ▸ On (two pickers, 4 taps). Draws two tick arcs, a pitch arrow, two roll ticks and, with a grid selected, the crosshair (40). Redraws continuously (a11y tree never idles). No numeric readout, no colour state, no auto-hide.

*Judgement:* it is an artificial-horizon instrument, not a level. On a phone held at arm's length you want one answer — "am I level" — and one direction to correct. ProShot draws one horizontal line with end ticks that turns green when level (93); MA Camera draws one bar with a centre dot on a dark shadow (92); Open Camera draws a single line + angle text and rotates the on-screen icons. Recommendation: replace the arcs with one bar + centre tick + roll angle, keep pitch as a small vertical tick only when the user is shooting downward (|pitch| > 45°), green within 0.5°, and stop invalidating when nothing changed.

## Optimizer result (zero-turn, `tools/critique/opt_run/`)

Space: permutation of 8 column items (7 existing + gallery) over a 2-column grid; rows above the shutter 1–3; shutter 72–96 dp; cell 40–56 dp; strip bottom/left/top; seekbar right/left. Components (all computable): thumb reach 0.30, grouping 0.15, preview clear 0.25, target size 0.15, strip reach 0.15. 60 generations × 24, HS+DE.

| grouping | 0.667 | 1.000 |

Winner: one row above the shutter (camera-switch, histogram), then directly below it **gallery + module**, **AE-lock + flash**, **timer + focus**; 56 dp cells; 72 dp shutter; strip at the bottom; **seekbar in the left band**. *Judgement:* the win is real but modest, and comes from three things that are worth doing regardless of the search: 56 dp cells (every target compliant), the two most-used items under the thumb, and the seekbar out of the crowded right band. The strip's bottom placement is the fixed cost in `preview_clear`; moving it to the left band scores the preview at 1.0 but costs strip reach (0.55) — I would not move it. ## What's working

- The capture core: JPEG, 16-bit DNG, JPEG+DNG, video, interval and AE bracket all produced correct files on the first try, into MediaStore and into a SAF folder.
- The NextGen settings drawer redesign: translucent scrim over the live preview, lime value column, ripple feedback, 48 dp rows, remembered tab — it reads as one system with the manual strip.
- Icon font as signature: 22 sp glyphs at 30 dp are crisp at 480 dpi and the lime "active" swap is unambiguous.
- Chrome restraint: 5 % ink coverage on the main screen; the histogram is placed in the letterbox band, not over the picture.
- The measured focal point is the shutter.
- Composition grids: nine patterns including golden-ratio variants, in a clean two-column picker.
- Build hygiene: AGP 8.13 / Gradle 8.14 / NDK 27 built clean in 5 minutes with 102 warnings, none fatal.

## Cannot verify

- `values-sw600dp` (tablet/foldable) scaling — no such device.
- Camera1 on other SoCs (MTK/Kirin vendor paths) — the LE2123 path NPEs before parameters load.
- Focus-stack merge output — the AF-bracket range is unsettable (priority 2), so the merge ran only with defaults and was not inspected.
- Tone-curve editor (`CurveViewControl`) — the button does not appear on this device (Camera2 tonemap not exposed).
- Physical-camera pinning — the Picture tab shows no "Physical Camera" row on this device.
- Level under real tilt — the phone lay flat; the ambiguity finding is from the rendering, not from a tilt sweep.
- Stock OnePlus, Fossify and Libre tap counts are read from their main screens, not walked (marked ≈).
- Italian rendering — the walk was in English by decision; the coverage number is from the resource files.
