# Purpose map and redundancy: findings (2026-10-20)

The question: can redundancy in GlassCam's screens and features be mitigated? The map is
[`docs/purpose-map.md`](../purpose-map.md) (source `purpose-map.json`, checked by `tools/purpose_map.py`).
This page records how it was made, what was found, and what is still the owner's call.

## Method

1. **Census from the code** (`tools/purpose_map.py --census`): 153 entries — 7 activities, 12 capture
   modules, 11 shutter-column toggles, 14 manual-strip controls, 90 settings rows, 4 gallery-viewer
   buttons, 15 fragments. Each carries what it sends to the camera (`writes`: the Camera2 request keys,
   read from the parameter classes themselves) and the camera API that offers it.
2. **Eight reference apps** inventoried from source trees and official docs (709 features):
   Open Camera 228, FreeDcam 177, ProShot 77, OnePlus Camera 76, MA Camera 53, Libre Camera 45,
   Fossify Camera 36, Manual Camera 17. Each feature was tagged with 1-2 of 21 facets
   (`facets.json`) and matched to the GlassCam entry that does the same job (same / partial / none).
3. **Purpose sets** (`purpose_sets.json`) are groupings of facets, so every set was scored on the same
   tags. The owner chose the axes: coverage, exclusivity, balance, GlassCam fit, potential improvement.

   | Set | Coverage | Exclusivity | Balance | GlassCam fit | Gaps under a named purpose |
   |---|---|---|---|---|---|
   | **E6** six purposes (chosen) | 1.00 | 0.77 | 0.91 | 0.92 | 364/364 |
   | D8 eight purposes | 1.00 | 0.75 | 0.87 | 0.91 | 364/364 |
   | B5 five, device/app outside | 0.82 | 0.62 | 0.89 | 0.82 | 276/364 |
   | C6 | 0.82 | 0.61 | 0.85 | 0.81 | 276/364 |
   | A7 | 0.82 | 0.59 | 0.84 | 0.81 | 276/364 |

   Caveats: coverage and "gaps under a named purpose" reward giving device/app settings a purpose of
   their own; exclusivity and balance favour fewer, larger purposes. E6 was chosen after a mock-up.
4. **Granularity** (owner's axes: redundancy it can see, review effort, upkeep, readability): G1 every
   control 138 entries / sees 100 %; G2 settings by section 55 / 67 %; G3 screens and modules 23 / 0 %;
   **G4 hybrid** (chosen) 91 / 100 % — settings by section, except rows in a candidate pair.
5. **Redundancy candidates**: 39 pairs from shared request keys, a code-verified same-job pass
   (`same_job.json`) and the tagger's notes; module variants (one per camera API or vendor, never
   both loaded) excluded. Ranked by Pareto layers, no weights (`candidates.json`, `tools/purpose/rank.py`).
   The owner rated "how often would you use it" only for the entries the OnePlus 6T actually shows
   (`use.json`).

## Candidates the 6T shows (with the owner's use ratings)

| Layer | Pair | Why | Use | Reading |
|---|---|---|---|---|
| 1 | Histogram / Histogram (camera hardware) | same job, same icon | sometimes / sometimes | **redundant and confusable**: the app histogram only exists with the OpenGL preview; the hardware one (Qualcomm ISP statistics) is the one in the normal preview |
| 1 | Flash / Auto Exposure Mode row | the AE mode row repeats the flash modes (auto flash, always flash, red-eye) | sometimes / often | **redundant**: two places to set flash behaviour |
| 1 | Focus mode / Manual focus | both write `CONTROL_AF_MODE` | often / often | a **coupling by design** (moving MF switches the mode), not a duplicate |
| 2 | Auto Exposure Mode / ISO | moving ISO off auto switches AE off | often / often | a **coupling**, not a duplicate |
| 2 | Edge Mode / Sharpness | both sharpen (Camera2 edge mode vs Qualcomm sharpness strength) | sometimes / sometimes | **overlapping**: two sharpening controls, neither says how they combine |

## Candidates the 6T never shows (code-level; matter on other phones)

Layer 1-3 on the code axes: Noise reduction / MFNR / Xiaomi MFNR (all write the noise-reduction mode;
the two MFNR rows share one description), HDR Mode / Scene and HDR Mode / Video HDR (Camera1), Camera
switch / Dual Camera / Physical Camera, Tone curve / Tonemap / ToneMapProfile, Dump vendor keys / Save
Camera Parameters (Camera2-only and Camera1-only versions of one job), Correlated Color Temperature /
White balance (Kelvin). Full list with axes: `candidates.json`.

## The owner's decisions (2026-10-20)

| Candidate | Decision |
|---|---|
| Histogram / Histogram (camera hardware) | **One button, best source**: hardware statistics where the phone has them, the app's own histogram only where it does not |
| Flash / Auto Exposure Mode row | **Flash toggle only**: the AE mode row keeps on/off; flash behaviour is set on the Flash toggle |
| Edge Mode / Sharpness | **Keep both, explain**: renamed so they read as two stages, each description says how they combine |
| MFNR / Xiaomi MFNR; Save Camera Parameters / Dump vendor keys | **Merge each into one row** (no visible change on the 6T or 9 Pro) |
| Focus mode / Manual focus; Auto Exposure Mode / ISO | not redundant: couplings by design, used often - kept |

## Fixes found on the way (not decisions)

- **The hardware camera key never takes a picture.** `KeyPressedController.startWork()` lists
  `KEYCODE_CAMERA`, but it is only reached from a held headset key (`onKeyDown`, line 66); a camera-key
  press only sets `activeKeyEvent`. The same method shows a hard-coded "Start Work" (T8).
- **"MNFR"**: `setting_mfnr_header` and `setting_xiaomimfnr_header` read "MNFR" for MFNR.
- **Rows that are probably never shown** (to verify): `SECONDARY_SENSOR_SIZE` (registration commented
  out, `ParameterHandlerApi2.java:278`), `SCENE_DETECT` (no feature detector), `COLOR_CORRECTION_MODE`
  (only added through `WbHandler`; its label "Correlated Color Temperature" reads like the Kelvin control).
- **The census has no entries for gestures and readouts** (tap to focus/meter, the info overlay's
  readouts, the waveform, the gallery's filter and multi-select): the map cannot place what it cannot see.

## What the reference apps do that GlassCam does not (potential improvement)

Recurring across apps: shutter on the volume keys (5 apps; GlassCam's volume keys step the active manual
control), a night mode that stacks frames (4), screen-brightness boost (4), panorama (3), pause/resume
video (3), saved manual presets C1/C2 (2), a photo while recording (2), an audio level meter (2), HEIC (2),
share from the gallery (FreeDcam had it). Per purpose: expand the lists in the mock-up
(`python tools/purpose/mockup.py E6`).

    python tools/purpose/mockup.py E6           # docs/purpose/mockup_E6.html

feature cites; the OnePlus 6T layout under OxygenOS 11 and Manual Camera's settings are thinly sourced.
